# Paper Reading（论文阅读）

## 概述

四模式按需调用：**速读 triage / 精读 / 批判 / 关联**，外加可选的**全文翻译**。每篇论文**只产出 1 个阅读文件**——全文翻译（若启用）与架构图（作者原图）全部整合在该文件内。

核心原则：**忠实原文、证据核查、只增不改、单文件交付。**

## 环境与配置

- **文献库根目录**：用户首次使用时告知；之后产出默认写入 `<文献库>/00-科学前沿探索`，或用户明确指定的其他目录。未配置时不要假设路径，先询问。
- **产出目录**：默认 `<文献库>/00-科学前沿探索`；用户指定时以其指令为准。
- **铁律：原 PDF 只读**——绝不修改、移动、重命名、删除任何原 PDF；所有产出仅以**新建文件**方式写入产出目录。
- **图片交付格式**：架构图存到产出目录下的 `figures/`，**文件名纯 ASCII**，md 中用相对路径外链（`![说明](figures/fig_01_xxx.png)`）。**不要用 base64 内嵌**（外链更易维护、文件更小）。base64 仅在用户明确要求单文件自包含时使用。
- 输入：本地 PDF 文件路径或 PDF 文件；未提供路径时先向用户索要，不猜测。

## 第零步：模式判定与读前询问

1. **模式判定**：用户指令含模式关键词（速读/精读/批判/关联）→ 直接进入对应模式；未指明 → 一轮询问（附四模式一句话简介 + 按场景推荐）。
2. **读前询问（可选，一轮完成）**：阅读目的、特别关注点、当前研究方向（供第 7 要素"对我研究的启发"使用）、是否需要全文翻译。
3. 用户明说"直接读"可跳过询问；但研究方向未知时，第 7 要素会缺乏针对性，可在笔记中注明"未提供研究方向，启发部分为通用建议"。

## 模式一：速读 triage

只读标题、摘要、图表、结论（不读正文细节），快速判断这篇论文是否值得精读。

产出内容：
- **一句话定位**：这篇论文做了什么
- **核心主张**：作者声称解决了什么、用的是什么思路
- **图表快速印象**：主实验结果是否支撑主张
- **取舍建议**：值得精读 / 值得局部精读（指明章节）/ 放弃，附理由

产出同样落盘（命名规则见下）。

## 模式二：精读

完整阅读全文（优先用 PyMuPDF 提取全文文本——部分 PDF 直接 Read 会返回二进制；含图表页），产出**固定 8 要素笔记**（既定模板，不得增删要素）：

1. **论文主题**：一段话说清这篇论文做什么
2. **模型名字 + 框架图**：框架图**必须是论文作者自己绘制的原图**（禁止 AI 自己理解后重绘，禁止 SVG/Mermaid 等任何再创作）。用 PyMuPDF 从 PDF 中定位架构图并提取作者原图：优先提取该页内嵌图片（`extract_image`）；无内嵌图片时渲染该页为高清 PNG 并裁剪出图区。图片存 `figures/`（纯 ASCII 名）、md 外链，并**逐模块文字讲解**（模块名 → 输入输出 → 在整体中的作用）。若论文有多张候选图，选作者用于展示整体架构的那张；确实无架构图时如实注明"原文未提供架构图"，不得代画
   - 裁剪定位技巧：先用 `page.search_for("Figure 1")`/`get_drawings()`/`get_image_info()` 找到图区 bbox，再按 bbox 内缩 2–5pt 裁剪（期刊 PDF 常有红色编辑框线，内缩可去掉）；裁完**必须逐张目检**，确认是架构图而非评估图
   - 若主图均为评估图（如某些纯方法学论文），如实注明"原文正文未提供架构图"，可附作者评估总览图但须标注其性质
3. **模型解决的现有挑战**：已有方法的局限、本文针对的痛点
4. **作者声称的模型创新点**：忠实转述作者的贡献声明，标注出处（引言/结论哪一段）
5. **实验结果**：主实验——做了哪些任务、用了哪些数据集、结果如何；**下游任务**——做了什么、结果如何、**主要用来验证什么**（如泛化性、表示质量、迁移能力）
6. **价值评估**：对照第 4 条逐项核查——实验证据是否真正支撑所声称的创新？在当前时间点该模型是否有价值？（结合联网检索判断是否已被后续工作超越）
7. **对我研究的启发**：针对读前询问得到的当前研究方向，给出可操作启发（可借鉴的方法、可改进的点、可结合的方向）
8. **整体质量评估**：方法严谨性、实验充分性、写作清晰度、可复现性综合评级（A/B/C）+ 理由

## 模式三：批判

审稿人视角通读全文，产出审稿意见式笔记：

- **方法漏洞**：设计缺陷、假设过强、理论依据不足
- **实验不充分处**：缺失的 baseline、消融不全、数据集偏窄、指标单一
- **过度声称**：结论超出证据支撑范围之处（逐条引原文对照）
- **创新性真实度**：与已有工作的实际差异有多大
- 总体判断：若作为审稿人，给 accept / borderline / reject 及理由

## 模式四：关联

联网检索（WebSearch）全网相关工作，产出定位分析：

- **同类工作对比**：与哪些论文直接相关，异同点表格
- **领域脉络**：该工作处在哪条技术演进线上（前驱 → 本文 → 可能的后续）
- **定位判断**：是开创、跟风、还是集大成
- 若产出目录中存在历史阅读文件，交叉引用对比，形成跨论文沉淀

## 全文翻译（可选，整合进阅读文件）

- 读前询问环节确认是否触发
- 全文翻译为简体中文；**专属英文名词保留英文原文**：模型名、方法名、数据集名、指标名、领域专有术语，首次出现时括号附中文释义
- 忠实原文：不省略、不意译压缩、不加译者观点
- **翻译作为附录章节附于阅读文件末尾**（如"附录：全文翻译"），不生成独立文件
- **翻译不替代笔记**：笔记主体仍按所选模式完整生成，翻译只是同一文件内的附加章节

## 产出与命名规则

**每篇论文只产出 1 个文件**，无论启用哪些模式与翻译，全部整合在内：

| 文件内容 | 命名 | 保存位置 |
|---------|------|---------|
| 阅读笔记主体（按所选模式）+ 架构图外链（`figures/`）+ 全文翻译附录（若启用） | `模型名字_YYYY-MM-DD_模式.md` | 产出目录 |
| 架构图 | `fig_NN_模型简称.png`（纯 ASCII） | 产出目录下 `figures/` |

- 日期取当天实际日期；"模型名字"取论文提出的方法/模型名（无模型名则取论文短标题）
- 同一篇论文跑了多个模式 → 各生成一个对应模式命名的文件
- 所有产出用简体中文撰写，专业术语保留英文（首现附中文释义）
- **绝不改动原 PDF 及文献库任何既有文件；产出目录缺失时先创建再写入**

## 批量阅读（>5 篇）

超过 5 篇时改用 `batch-paper-reading` 技能（多代理并行架构），不要在单会话里逐篇精读。

## 交付与精修

交付笔记后附 2-3 个可精修方向（如：详略调整、批判深度加深、框架图讲解颗粒度细化）供用户选择；除读前询问和交付精修外不多问，避免打断阅读节奏。

## 常见错误

| 错误 | 纠正 |
|------|------|
| 修改/移动/删除原 PDF，或在文献库写入任何文件 | 铁律禁止，产出只写入用户指定目录 |
| AI 自己理解后重绘框架图（SVG/Mermaid/示意画法） | 只允许论文作者原图，PyMuPDF 提取/渲染后存 `figures/` 外链 |
| 用 base64 内嵌图片 | 默认外链；仅用户要求单文件自包含时用 base64 |
| 图裁完不检查就写入报告 | 必须逐张目检：确认是架构图（不是评估图）、无期刊红框、无文字截断 |
| 生成翻译或架构图的独立文件 | 全部整合进唯一的阅读文件，单文件交付 |
| 翻译时把模型名/数据集名/指标名也翻成中文 | 专属名词保留英文原文 |
| 用翻译替代模式笔记主体 | 笔记主体在前、翻译只作附录，缺一不可 |
| 速读场景也走 8 要素重流程 | 按模式走对应流程 |
| 价值评估只复述作者声称 | 必须对照实验证据核查 + 联网核实时效性 |
| "启发"写成对任何人都成立的泛泛之谈 | 必须针对用户读前说明的研究方向 |
