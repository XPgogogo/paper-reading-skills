# Batch Paper Reading（批量论文精读：多代理工作流）

## 适用场景
用户要求精读一个文件夹（含多个子文件夹、20 篇以上 PDF）并交付"总报告 + 每个子文件夹综合报告"（综合分析在前 + 逐篇 8 要素笔记在后）。单个会话上下文无法装下全部论文全文时，必须用本工作流。

## 总体架构
1. **主会话**：规划分批、启动代理、汇总各批摘要、撰写各级报告的"综合分析"头部、最终装配与校验。
2. **笔记代理**（每批 3-6 篇）：PyMuPDF 提取全文到文本缓存 → 通读 → 提取作者原图架构图 → 写 8 要素笔记草稿 → 返回每篇一行的精炼摘要（含有意义:高/中/低 + 质量A/B/C）。
3. **装配脚本**（assemble.py）：报告头部（主会话撰写）+ 逐篇笔记拼接，笔记标题降一级（H1→H2、H2→H3，注意是加 `#` 不是加 `# `，否则产生 `# #`）。
4. **总报告**：全部批次摘要汇总后由主会话撰写（领域全景/演进脉络/路线对比/有意义工作清单/跨路线共识）。

## 关键经验（血泪教训）

### 0. 开工前先精确点数——最容易犯的错
- 用 manifest 逐篇核对每个子文件夹的**真实篇数**，不要凭第一眼目录列表估。曾把 14 篇当成 12 篇，两篇漏读，直到全部代理跑完、比对 manifest 才发现，只能补跑。
- 分批时把 manifest 的 key 列表打印出来逐个勾，不要按"文件夹名 → 批次数"心算。

### 0.1 图片质量：必须自动筛查 + 批量目检（最重要）
代理经常裁到**正文页**而不是图（候选页规则太窄导致），且自检会谎报"已目检通过"。可靠做法：

1. **自动初筛**：对 `figures/*.png` 计算彩色像素占比（`max(r,g,b)-min(r,g,b)>30` 的比例），低于 0.02 的列为"疑似正文页/灰度图"。
2. **批量目检**：把可疑图用 PIL 拼成 contact sheet（每格带文件名红字标注），**一次看 9–15 张**，而不是逐张看。这一步能在几分钟内筛出全部错图。
3. 修复时按"**图片数量 ≥2 的页**"重新扫描 PDF，不要只搜 "Figure 1"：
   - `ARTICLE IN PRESS`（Nat Commun in-press）与 bioRxiv 版式把图放在**文末**；
   - Wiley 投稿稿把图放在**正文后的单独页**；
   - 部分期刊 Figure 1 是整页大图，要整页裁。

### 0.2 图片内容去重
同一张图重复查看会返回"图片未变化"而看不到内容。把图另存为 JPEG（quality 85）再查看即可绕过。

### 0.3 预处理分工比让代理自己调 PyMuPDF 更稳
主会话先用一个 `prep.py` 一次性完成：全文 txt 导出 + 候选页渲染（180–200 dpi）+ manifest.json（含 sub/file/cands/pages）。代理只读 txt + 看候选 PNG，再用统一的 `crop.py <cand> <out> x0 y0 x1 y1`（**0~1 相对坐标**，代理看图就能估）裁剪。比每个代理自己写 PyMuPDF 代码快且一致。

### 1. TPM 限流（429）应对
- 大模型 API 常有组织级 TPM 限制。**高并发必炸；安全区间是 2-4 个并发**。
- 失败规律：新代理在启动后 1-4 分钟的"初始化+首批全文读取"峰值最易阵亡；已运行一段时间的代理反而能存活。
- 正确策略：**分波启动**（每完成一个再启动一个，维持低并发）；给代理写明"遇 429 等待 60-120 秒重试，不要放弃"。
- 代理失败 ≠ 工作丢失：常在失败前已完成大部分产出，**先查磁盘再决定重跑范围**。

### 2. 防误删铁律——第二重要
- **绝不下达含糊的清理指令**（如"只保留最终选定文件"——代理会把别人的成品当中间文件删掉）。
- 正确写法："你只允许【创建】文件 figures/<key>.png；绝不删除/移动/重命名任何已有文件；你自己的中间文件也不删，由主会话统一清理"。
- 共享目录（figures/、_drafts/）中多代理并行时，可在关键成品上加只读锁（chmod 444）防护。

### 3. 路径必须写全
- 给代理的输出路径**逐字写绝对路径**，禁止 `.../阅读报告` 之类缩写——有代理按相对路径解析，把大量文件写进了文献库源文件夹（文献库本应只读），需事后抢救搬迁+清理。

### 4. 乱码判断先验证再行动
- Git Bash 下 `cut -c` 按字节截断 UTF-8 中文会产生乱码**假象**；判断文件是否真乱码必须用 Python 按字符解码验证（utf-8 能否完整解码）。

### 5. 代理恢复
- 中断的代理可通过重新 spawn 恢复；若原平台支持消息续跑，优先用续跑保留上下文。
- 后台代理全部停止后消息通道会失效。

### 6. 笔记模板要点
- 8 要素固定结构；第 6 要素末尾强制单独一行"**有意义的工作：高/中/低 —— 一句话理由**"，便于主会话 grep 汇总。
- 提醒代理：模板中的括号说明文字不要原样抄进标题。
- 图片链接统一写相对路径 `figures/<key>.png`（即使笔记草稿在子目录，最终报告装配后正好对齐）。

### 7. 批量删除安全机制
- 大批量删除文件前先向用户确认；中间文件清理分批进行，避免误删成品。

## 最终校验清单
1. 无 `data:image` 残留；
2. 报告中全部 `![](...)` 链接与实际文件逐字核对（用 Python 正则提取+os.path.exists）；
3. 图片文件名纯 ASCII；
4. 笔记数 = 论文数；图片数 = 论文数 **减去确无架构图的篇数**，差额要能在笔记里逐篇说清；
5. 彩色占比 <0.02 的图全部目检过；
6. 清理中间文件（保留规范图 + 报告），解锁只读属性；
7. 交付前把**各子报告的分级表与逐篇笔记的评级对齐**——代理写的 `**有意义的工作：高/中/低**` 才是权威，主会话手写的表容易与它不一致。

- 提示用户用 Markdown 编辑器（如 VS Code `Ctrl+Shift+V`）预览看图。
