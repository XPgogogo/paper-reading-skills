# 框架契约模板（Step 1 产出物）

框架契约是整个写作过程的核心工作文件：用户确认后，Step 2 每章写作强制回读，Step 3 质检作为比对基准，Step 4 LaTeX 化按其中的文件命名清单生成工程。保存为项目工作文件（建议命名 `contract.md`，与论文稿同目录），长对话中断后凭此文件恢复状态。

## 填写规则

1. **挑战与贡献必须闭环**：每条贡献至少对应一个挑战的论证链；反过来，每个挑战的方案落点必须是某条贡献。对不上就是框架漏洞，需回到深挖阶段。
2. **衔接设计不可空**：每章的"开头衔接/结尾过渡"必须写具体内容（接什么、抛什么），写"自然过渡"四个字视为未完成。
3. **文件命名清单在契约确认时生成**：图表语义名在 Markdown 阶段就作为占位符使用（如 `【图 Figure2_architecture】`），LaTeX 化时直接映射，中途新增图表须同步登记清单。
4. **契约是活文档**：写作中若发现框架问题（如某个 gap 证据不足），需提出契约修订并经用户确认，禁止悄悄改。
