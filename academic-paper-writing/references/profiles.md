# Style Profile 配置表

每套 profile 分两部分：**结构规范**（硬约束，机器可查）与**文风基准**（默认写作风格，被用户样本论文提取的文风画像覆盖/精调）。

## Profile 匹配规则

- 用户给出明确期刊/会议 → 按下表匹配；匹配不到 → 询问用户后按最接近的 profile 执行并说明差异
- 新期刊扩展：按下表格式填一行即可，不新增逻辑

---

## 一、结构规范（硬约束）

| 字段 | P1 ML 顶会类 | P2 IEEE/ACM 期刊类 | P3 生信专业刊 | P4 Nature 系 |
|------|--------------|--------------------|----------------|----------------|
| 代表刊物 | NeurIPS, ICML, ICLR, AAAI, IJCAI | TPAMI, TNNLS, IoT-J, Bioinformatics (proc版) | Bioinformatics, Genome Biology, Briefings in Bioinformatics | Nature Methods, Nature Biotechnology, Nature Communications |
| 结构模板 | 正文 8 页 + Appendix 无限 | 双栏 12–14 页，Method 在中段 | 应用/方法导向，篇幅严格 | 正文简短（3.5k–5k 词），Methods 后置或独立 |
| 引用风格 | author-year（natbib: \citep/\citet） | numbered（\cite → [1]） | numbered 为主 | numbered，文献数受限 |
| 语态偏好 | 适度主动 | 传统学术被动居多，现代趋势主动 | 主动为主 | 明确主动语态 |
| 图表引用惯例 | Figure/Fig. 皆可，正文缩写 Fig. | Fig. + Table，严格编号 | Figure 全拼居多 | Fig. + 详尽图注体系（Extended Data） |
| 特殊要求 | Checklist、Reproducibility 声明 | 图表内嵌、公式编号按章 | 软件可用性声明、数据可得性 | 字数硬限制、图注详尽、Methods 按 Nature 格式 |

## 二、文风基准（默认写作风格，无用户样本时按此执行）

| 维度 | P1 ML 顶会类 | P2 IEEE/ACM 期刊类 | P3 生信专业刊 | P4 Nature 系 |
|------|--------------|--------------------|----------------|----------------|
| 叙述节奏 | 快节奏，直入主题，段落紧凑 | 稳健铺陈，论证充分，段落较长 | 方法细节优先，务求可复现 | 高度凝练，每句信息密度极大 |
| 论证密度 | 重直觉与实验证据，理论从简 | 重理论严谨，推导完整 | 重流程与验证，统计表述规范 | 重发现与意义，技术细节后移 |
| 句式特征 | 短句为主，主动语态，we 主语高频 | 长句可接受，被动结构容忍度高 | 中等句长，精确术语优先 | 短中句，主动语态，动词有力 |
| 贡献陈述 | Intro 末尾 bullet 式贡献列表，逐条对应实验 | 行文式贡献陈述，含理论/实验两分 | "应用价值+方法改进"双线陈述 | 避免罗列式贡献，融入叙事主线 |
| 修辞惯例 | 敢用强断言（"we substantially outperform"） | hedging 中等，结论克制 | 克制陈述，强调 benchmark 与 p-value | 首段即讲大图景与领域影响 |
| 章节气质 | Intro 直入主题，一页内见到方法 | Intro 宏观铺垫 1.5–2 页 | Intro 快速交代生物学动机 | 开篇即抛核心发现 |

## 三、文风校准流程（Step 0 执行）

用户提供目标期刊 2–3 篇代表性论文时，提取**文风画像**（写入框架契约，覆盖上表默认值）：

| 提取维度 | 观察内容 |
|----------|----------|
| 叙述节奏 | 段落长度分布、每段承担的论证量、Intro 展开的快慢 |
| 论证密度 | 论点与证据的配比、公式推导详略程度、实验解读深度 |
| 句式特征 | 平均句长、从句嵌套习惯、主动/被动语态实际比例 |
| 修辞惯例 | 贡献如何陈述（bullet 还是行文）、过渡句风格、hedging 强度 |
| 章节气质 | Intro 是宏大叙事还是直入主题、Related Work 是批判性还是描述性 |

无样本论文时：按上表 profile 默认文风执行，并向用户说明这是通用校准，建议后续补样本精调。
